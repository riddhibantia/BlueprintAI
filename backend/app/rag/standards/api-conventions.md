# API Conventions (default pack)

Baseline HTTP/JSON conventions for services generated by BlueprintAI. Replace
this file with your own standard when your team already has one.

## Resource naming and routes

- Nouns, plural, lower-case, hyphen-separated: `/expense-reports`, `/team-members`.
- Never put verbs in a path. `POST /expense-reports/{id}/approve` is acceptable
  only for a state transition that has no natural resource form.
- Nest at most one level: `/projects/{project_id}/documents`. Deeper ownership
  belongs in the query string or a dedicated resource.
- Every route is scoped by tenant or project id; a handler that cannot name the
  scope it enforces is a bug.

## Methods and status codes

- `GET` is safe and side-effect free. `PUT` replaces, `PATCH` partially updates,
  `DELETE` removes or tombstones.
- `200` for a returned representation, `201` + `Location` for creation,
  `204` for a successful delete with no body.
- `400` for malformed input, `401` for missing/invalid credentials, `403` for
  authenticated-but-not-allowed, `404` for missing or hidden resources, `409`
  for state conflicts (including optimistic-lock failures), `422` for
  semantically invalid fields, `429` for rate limits.
- Never return `200` with an error object in the body.

## Error envelope

Every non-2xx response uses one shape:

```json
{"error": {"code": "validation_failed", "message": "human readable", "details": [{"field": "amount", "issue": "must be positive"}]}}
```

`code` is stable and machine-readable; `message` is safe to show a user and
never contains a stack trace, SQL, or internal path.

## Pagination, filtering, sorting

- Cursor pagination by default: `?limit=50&cursor=...`, response carries
  `{"items": [...], "next_cursor": "..."}`.
- Offset pagination only for admin screens that need page numbers.
- `limit` is capped server-side (default 50, maximum 200). An uncapped limit is
  a denial-of-service vector.
- Filters are explicit query parameters; no arbitrary field expressions from
  the client.

## Request validation and idempotency

- Validate at the boundary with a schema; reject unknown fields on writes.
- All timestamps are ISO 8601 UTC (`2026-10-29T09:15:00Z`). Money is an integer
  in minor units plus a currency code, never a float.
- Write endpoints that create money-moving or externally visible resources
  accept an `Idempotency-Key` header and replay the first response for repeats.

## Versioning and documentation

- Breaking changes ship under a new path prefix (`/v2/...`); additive fields do
  not require a version bump.
- The OpenAPI document is generated from the code, never hand-maintained.
- Every endpoint declares its auth requirement, success schema and error codes.
