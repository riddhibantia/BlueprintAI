# Security Baseline (default pack)

Minimum security requirements for any service generated by BlueprintAI. A
generated artifact that violates one of these rules is a defect, not a style
preference.

## Authentication

- Sessions use short-lived access tokens (15-120 minutes) and a rotating
  refresh token. Tokens are signed with a per-environment secret of at least
  32 bytes, never a default value in production.
- Passwords are hashed with Argon2id or bcrypt (cost >= 12). Plaintext,
  reversible encryption and unsalted hashes are forbidden.
- Browser sessions use `HttpOnly`, `Secure`, `SameSite=Lax` cookies. Tokens are
  never stored in `localStorage`.
- Failed logins are rate limited per account and per IP; the response does not
  reveal whether the email exists.

## Authorization

- Every request is authorized server-side against the resource's owner or
  tenant. Hiding a button in the UI is not authorization.
- Deny by default: a route without an explicit permission check fails closed.
- Object access checks happen on the loaded row (`row.owner_id == user.id`), not
  on an id supplied by the client. This is the IDOR guard.
- Multi-tenant tables carry a tenant or project id, and every query filters on
  it. Cross-tenant reads return `404`, not `403`, to avoid leaking existence.

## Input and output handling

- Validate type, length, range and encoding at the boundary; reject unknown
  fields on writes.
- Parameterize every SQL statement. String-built queries are rejected in review.
- Escape output for its context. User content rendered as HTML is sanitized
  with an allow-list.
- Uploads are limited by size and extension, parsed in a sandboxed path, and
  never executed or served with an attacker-controlled content type.
- Redirect targets and outbound URLs are allow-listed to prevent SSRF and open
  redirects.

## Secrets and configuration

- Secrets come from the environment or a secret manager. No key, token or
  password is committed, logged, or embedded in a client bundle.
- Production configuration fails closed: a default JWT secret, wildcard CORS
  with credentials, or a debug flag enabled stops the process from booting.
- CORS allows explicit origins only. `*` combined with credentials is forbidden.

## Data protection and logging

- Sensitive fields (passwords, tokens, government ids, card data) are never
  written to logs, traces or audit detail; the audit helper redacts them.
- TLS is required in transit; encryption at rest is enabled for the database and
  object storage.
- Logs record who did what and when, but not the contents of user documents.
- Personal data has a defined retention period and a deletion path.

## Dependencies and supply chain

- Dependencies are pinned and scanned in CI; a known critical advisory blocks
  merge.
- No package is added without a maintained release and a licence compatible with
  the project.
- CI runs with least privilege; deployment credentials are not available to pull
  requests from forks.
